## 找題目檔案：在實際專案目錄


## Docker：在主機

| 目的 | 命令 |
|---|---|
| 找容器與狀態 | `docker ps -a` |
| 啟動既有容器 | `docker start 容器名` |
| 開 shell | `docker exec -it 容器名 bash` |
| 查主機資料夾接到哪 | 見下方 inspect |

```bash
docker inspect 容器名 --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

**家用的容器名是 srecruit-demo、內部程式路徑是 /demo。** 正式考場查現場設定。建立新容器的長命令留在 [Docker 頁](技術/Docker.md)。

## ROS 環境：在題目指定 shell／容器

找不到 ros2 時，確認已載入該版本環境：

```bash
ls /opt/ros
source "/opt/ros/<實際版本>/setup.bash"
```

本 repo 容器用 Jazzy：`source /opt/ros/jazzy/setup.bash`。每個新 shell 的環境各自設定。

## ROS：依問題選命令

| 我想知道 | 指令 |
|---|---|
| 哪些功能單位在跑 | `ros2 node list` |
| processor 訂閱／發布哪裡 | `ros2 node info /processor` |
| 通道與型別 | `ros2 topic list -t` |
| 某通道的型別 | `ros2 topic type /number` |
| 發／收端點與 QoS | `ros2 topic info /number --verbose` |
| 訊息欄位 | `ros2 interface show std_msgs/msg/Int32` |
| 真的有輸入嗎 | `ros2 topic echo /number` |
| 真的有輸出嗎 | `ros2 topic echo /double` |
| 收到多快 | `ros2 topic hz /number` |
| 單次發送 | `ros2 topic pub --once /number std_msgs/msg/Int32 '{data: 21}'` |
| 查 domain | `printenv ROS_DOMAIN_ID`，空白時查環境預設 |

echo 是持續觀察，Ctrl-C 停止。已啟動處理者／接收者後，pub 才有對象；同時有其他 publisher 時會混入它們的資料。本 repo 目前 21→64，官方原公式 21→42。

看到 package 形式才查其 README：

```bash
colcon build --packages-select "<套件名>"
source install/setup.bash
ros2 run "<套件名>" "<執行目標>"
```

本 repo 的 processor 是直接 `python3 processor.py`，不使用這段 package 指令。概念與無輸出查法見 [ROS 2](技術/ROS2.md)。

## C／Make／CMake：在對應專案目錄

| 想做什麼 | 指令與適用情況 |
|---|---|
| 看 Make 預計做什麼 | `make -n`，一般情況列出預計 recipe |
| 看目標有什麼 | 讀 Makefile；專案有 help 才用 `make help` |
| 建置指定目標 | `make 目標名`，名稱按題目 |
| 已配置 CMake，重新建置 | `cmake --build "<建置目錄>"` |
| 單檔主機 C 範例 | `cc -O0 -g -Wall -Wextra main.c -o app`；需真的有 main.c |
| 使用 pthread 的主機 C | 上面再加 `-pthread` |

板子程式用題目工具鏈。編譯成功、執行新程式、寫入新韌體是不同步驟，查 [編譯與 Make](技術/編譯與Make.md)、[Pico SDK](技術/RP2350與PicoSDK.md)。

## 板子與串口：在能存取 USB 的環境

```bash
ls /dev/serial/by-id/
ls /dev/ttyACM* /dev/ttyUSB*
```

有工具才用：`python3 -m serial.tools.list_ports`。裝置名、baud、燒錄方式依題目；正式接收程式正在讀時，不另開 monitor 搶資料。[封包格式](技術/序列通訊與封包.md) · [ESP32 工具](技術/ESP32.md)

## 拉筆記與提交：在正確 Git repo

```bash
git status --short --branch
git branch -vv
git remote -v
git diff
git diff --check
```

只讀這份筆記、本機在 main 且修改可安全保留時：`git pull --ff-only origin main`。沒 tracking／有衝突請查 [Git 與提交](技術/Git與提交.md)，別用 reset --hard 解決。

正式交卷依現場題目指定的分支、檔案與提交方式，不能把這份筆記的 GitHub 當考試 GitLab。

## nvim 看筆記

| 命令 | 用途 |
|---|---|
| `:w` | 存檔 |
| `/關鍵字`，再按 n／N | 搜尋下一個／上一個 |
| `:set wrap linebreak` | 長行在畫面換行 |
| `:set conceallevel=2` | 語法支援時隱藏部分 Markdown 標記，不保證完整渲染 |
| `:checktime` | 外部更新後檢查檔案變動 |

要看完整表格排版，可用瀏覽器打開 GitHub 上的 Markdown。nvim 基本語法顯示不等於網頁渲染。
