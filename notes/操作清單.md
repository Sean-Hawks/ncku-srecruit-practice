# 看懂原理，指令查表

練習時，先想清楚「我要確認什麼」，再複製對應指令。Docker 建環境的長指令留在最後，需要時才展開。

## 需要理解的六件事

| 主題 | 能用自己的話解釋就夠 |
|---|---|
| ROS | 誰發送、誰接收、哪一行計算、結果送到哪裡 |
| 位元 | 哪些位置保留，哪些位置改掉 |
| 共享變數 | 兩邊先讀舊值，為何可能覆蓋更新；鎖包住哪幾步 |
| 搬運引擎 | count 是筆數；啟動後何時才能使用結果 |
| PIO | 每條指令把資料從哪個暫存器搬到哪裡 |
| Docker | 主機哪個資料夾對應容器哪個路徑；存檔後要重啟 Python |

**不用默寫完整 Docker、ros2、編譯指令。** 能挑對操作、替換檔名或 topic，再用結果驗證。

## 平常練習：只看這一段

### 1 在主機修改程式

```bash
cd ~/Development/ncku-srecruit-practice
nvim demo/section2-1/processor.py
```

改完用 `:w` 存檔。

### 2 進入已建好的 container

在主機終端機貼上：

```bash
docker exec -it srecruit-demo bash
cd /demo/section2-1
```

後面的 ROS 指令都在這個環境裡跑。每個新終端機都要進入同一個 container。

### 3 測試一個已知輸入

先停止 publisher.py，避免隨機數混進來。三個終端機都先完成上一步。

**A：執行處理程式。** 沒訊息時安靜等待是正常的。

```bash
python3 processor.py
```

**B：先觀察輸出，保持執行。**

```bash
ros2 topic echo /double
```

**C：送入一次 21。**

```bash
ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"
```

| processor.py 的實際計算 | A 印出 | B 收到 |
|---|---|---|
| `received.data * 2` | received: 21 | data: 42 |
| `received.data * 3 + 1` | received: 21 | data: 64 |

改程式後：**存檔 → 在 A 按 Ctrl-C → 重跑 processor → 在 C 重送 21。**

## ROS 卡住時，照問題選指令

以下在 container 裡執行；需要時另開終端機。

| 我想確認什麼 | 直接複製 |
|---|---|
| processor 有沒有啟動 | `ros2 node list` |
| processor 訂閱、發布到哪裡 | `ros2 node info /processor` |
| topic 名稱與型別 | `ros2 topic list -t` |
| /number 有沒有發送與接收端 | `ros2 topic info /number` |
| 原始輸入是多少 | `ros2 topic echo /number` |
| 算完的輸出是多少 | `ros2 topic echo /double` |

`echo` 只顯示收到的資料。它接收 /number 不需要經過 processor：

```text
                         ┌→ echo /number：印出 21
送入 /number 的 21 ───────┤
                         └→ processor：計算 → /double → echo /double
```

/double 是名稱；乘二或乘三發生在 Python 程式裡。接收者不會因名字叫 double 就自動乘二。

## 修改後結果沒變：查這三項

1. nvim 有沒有用 `:w` 存檔？
2. 有沒有停止舊 processor，再重跑？
3. 主機和 container 是否讀到同一份檔案？

第 3 項在**主機**貼上：

```bash
cd ~/Development/ncku-srecruit-practice
rg 'out.data =' demo/section2-1/processor.py
docker exec srecruit-demo grep 'out.data =' /demo/section2-1/processor.py
```

兩邊應顯示同一個計算式。不同時先查掛載，別繼續改計算。

## Docker 管理：有需要才展開

<details>
<summary>查看 container、進入環境、停止後重開</summary>

以下都在主機執行：

```bash
docker ps -a
docker exec -it srecruit-demo bash
```

第一條是列出 container；第二條是進入已執行的環境。若 srecruit-demo 已停止，先執行：

```bash
docker start srecruit-demo
```

需要停止整個環境時：

```bash
docker stop srecruit-demo
```

停止會中斷裡面正在跑的程式；重新 start 後，要自行重開 publisher、processor 和 echo。

</details>

<details>
<summary>查掛載：外面哪個資料夾對應裡面哪裡</summary>

在主機貼上：

```bash
docker inspect srecruit-demo --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

目前應對應：

```text
/home/hawks/Development/ncku-srecruit-practice/demo -> /demo
```

你在哪個主機資料夾執行 docker exec，不會改變既有掛載。

</details>

<details>
<summary>另建 container 並指定資料夾：不用背，改 src</summary>

現有 srecruit-demo 已建好。下面用另一個名字 my-practice 示範；image 已存在時，在主機貼上：

```bash
docker run --rm -it \
  --name my-practice \
  --mount type=bind,src=/home/hawks/Development/ncku-srecruit-practice/demo,dst=/demo \
  srecruit-demo bash
```

- src：主機上要使用的資料夾。
- dst：container 內看到的位置。
- srecruit-demo：環境 image 名稱。
- my-practice：這次新建的 container 名稱。

要再進入這個示範 container，另一個主機終端機執行：

```bash
docker exec -it my-practice bash
```

最初的 bash 離開後，這個示範 container 會因 --rm 刪除；掛載在主機上的檔案仍保留。已存在的 container 要換掛載，重新建立時再指定。

[官方掛載文件](https://docs.docker.com/engine/storage/bind-mounts/)

</details>
