## Docker：在哪裡改、在哪裡跑

| 名稱／操作 | 意思 |
|---|---|
| image | 環境範本 |
| container | 由範本建立的執行環境 |
| COPY | 建 image 當下的檔案快照 |
| bind mount | 將主機路徑接到容器路徑，兩邊看同一份檔案 |
| `docker ps -a` | 在主機列容器與狀態 |
| `docker start 容器名` | 啟動已存在的容器 |
| `docker exec -it 容器名 bash` | 進正在執行的容器開 shell |
| `docker run` | 建立新容器；不是進入舊容器 |

**主機 cd 到別處不會改掛載。** 檔案是否同步，用主機 inspect 查：

```bash
docker inspect 容器名 --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

Source 是主機來源，Destination 是容器路徑。你家用的對應是 `~/Development/ncku-srecruit-practice/demo` → `srecruit-demo` 裡的 `/demo`。先前失效原因是掛到另一份舊 repo；考場查現場對應，不套家用路徑。

讀寫 mount 下，容器刪檔也會刪主機檔案。USB／網路是另外的配置，不能因進了容器就假設看得到板子。

## 改了沒生效

```text
:w 存檔 → 確認是同一份檔案 → 需要時重編譯 → 重啟程序／寫入板子
```

| 改了什麼 | 接著做什麼 |
|---|---|
| Python 原始碼 | 停止舊程序，重新執行 |
| C/C++ | 重新建置，再跑新執行檔 |
| 板子韌體 | 建置後寫入對應板子，再按介面重新連線 |
| Dockerfile／依賴環境 | 才需要處理 image 建置；一般掛載原始碼修改不需重建 image |

## 編譯與 Make

**make 讀規則；cc／gcc／clang 編譯；linker 將實作接成執行檔。** `.h` 宣告有哪些函式，`.c` 定義函式怎麼做；include engine.h 不會自動把 engine.c 編進去。

| 專案 | 查閱命令 |
|---|---|
| Makefile | `make -n` 看預計命令；`make 目標名` 建置／執行指定目標 |
| 已配置 CMake | `cmake --build "<建置目錄>"` |
| 單檔主機 C | `cc -O0 -g -Wall -Wextra main.c -o app`，需真的有 main.c |
| 主機 pthread 程式 | 編譯／連結加 `-pthread` |
| 板子程式 | 用題目指定交叉編譯器，不能直接用主機 cc |

`-o` 指定產物、`-I` 加 include 路徑、`-g` 加除錯資訊、`-O2` 做最佳化。正式效能比較固定編譯選項。

| 錯誤 | 先查 |
|---|---|
| header 找不到 | SDK、include 路徑、目前 shell |
| undefined reference | 少編 .c、少連結 library、名稱不符 |
| No rule to make target | 目標名與目前目錄 |
| Nothing to be done | 改的是不是依賴檔、是否在正確專案 |
| missing separator | Make recipe 開頭通常要 Tab |

本 repo `/demo/section2-3`：`make` 建置；`make run-transfer-engine` 建置後執行；`make mistake` 加 --mistake 展示錯誤筆數。不是每個題目都有這些目標。

## Git：更新筆記與交卷

首次拿考試程式：GitLab專案的 Code 按鈕複製網址，再用 `git clone "<複製的網址>"` 下載到指定電腦／環境；已有專案時用其現有目錄。下載後的板端建置與寫入，查 [GitLab到板子的流程](技術/RP2350與PicoSDK.md#從-gitlab-到板子先看這條路)。git clone／pull／push 都不會自行燒錄板子。

先 `git status --short --branch`、`git remote -v`、`git branch -vv` 確認 repo／分支／遠端。

拉這份筆記，本機在 main 且修改不衝突時：

```bash
git pull --ff-only origin main
```

沒有 tracking：確認 main 確實要追 origin/main，再設定：

```bash
git fetch origin
git branch --set-upstream-to=origin/main main
```

有本機修改／分歧時先看 `git diff`，保留自己的工作；不用 reset --hard 處理。commit 是存本機，push 才上遠端。

正式提交在**考試 repo**，檔案／分支／訊息依現場規格：

```bash
git diff --check
git add "<本次要交的檔案>"
git diff --cached
git commit -m "<提交訊息>"
git push
```

push 成功後再看指定的評分結果；不代表自動通過。私人 GitHub 筆記與考試 GitLab 是不同 repo。

## nvim 看筆記

`:w` 存檔；`/關鍵字` 搜尋，n／N 前後跳；`:set wrap linebreak` 畫面換行；`:checktime` 檢查外部更新。完整表格排版直接開 GitHub 網頁。
