## 建議練習順序

### 1. 先練 ROS 2 CLI：`section2-1`

這一段的目標是看到一條完整的資料流：

```text
/publisher -> /number -> /processor -> /double
```

開三個終端機，每個都執行：

```bash
docker exec -it srecruit-demo bash
cd /demo/section2-1
```

終端機 A：

```bash
python3 publisher.py
```

終端機 B：

```bash
python3 processor.py
```

終端機 C 依序觀察：

```bash
ros2 node list
ros2 topic list
ros2 node info /publisher
ros2 node info /processor
ros2 topic info /number
ros2 interface show std_msgs/msg/Int32
ros2 topic echo /double
ros2 topic hz /number
```

接著在 A 按 `Ctrl-C` 停止 publisher，保持 processor 和 echo 執行，在 A 改用 CLI 發送一筆資料：

```bash
ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"
```

C 應看到：

```text
data: 42
```

這段最值得熟練的是除錯順序：先確認 node，再確認 topic，再看 node 是否接到正確 topic，接著看 publisher/subscriber 數量，最後用 `echo` 確認實際資料。可以再試兩個小題：把 topic 名稱故意改錯一個字元，或同時啟動兩個 publisher，觀察 `ros2 topic info /number` 的變化。

### 2. 再練位元運算：`section2-2`

執行：

```bash
docker exec -it srecruit-demo bash
cd /demo/section2-2
cc demo_asm.c -o demo_asm
./demo_asm
```

不要只看輸出。每次先遮住註解，自己算出以下幾類操作，再編譯驗證：

- `x & mask`：取出欄位
- `x | (1u << n)`：設定第 `n` 位
- `x & ~(1u << n)`：清除第 `n` 位
- `(x >> n) & 1`：讀取第 `n` 位
- `(x >> hi) & mask`：取出連續欄位
- `(a << 8) | b`：把兩段值組合起來

`demo_pio.pio` 只要閱讀。練習說明 CPU、TX FIFO、OSR、X、ISR、RX FIFO 之間的資料流，以及 `out`、`in`、`push` 各自做什麼；不需要編譯或燒錄。

### 3. 最後練 pthread 與資料搬運：`section2-3`

執行：

```bash
docker exec -it srecruit-demo bash
cd /demo/section2-3
make run-critical-section
make run-transfer-engine
make mistake
```

先反覆跑 `make run-critical-section`，確認你能說明三行的差別：

1. 沒有鎖：`counter++` 的讀、加、寫可能互相覆蓋。
2. 短鎖：只鎖共享變數的存取，結果正確且較快。
3. 長鎖：把耗時工作也鎖住，結果正確但兩個 thread 幾乎排隊執行。

接著用 transfer engine 記住固定四拍：

```text
configure -> start -> wait/busy -> 使用結果
```

練習時要特別檢查三件事：`count` 是傳輸筆數，不是 bytes；來源和目的位址是否遞增；每筆大小是否為 1、2 或 4 bytes 且已對齊。`make mistake` 會示範把 16384 bytes 誤當成 count，結果實際搬了 16384 筆。

## 一次練習的節奏

建議第一次花約 90 分鐘：

- 30 分鐘：完整走過 ROS 2 三個終端機流程，並做一次 CLI 注入。
- 20 分鐘：手算並改寫 `demo_asm.c` 的位元操作。
- 30 分鐘：反覆比較三種 critical section，再跑 transfer engine 與 mistake。
- 10 分鐘：不看 README，從記憶寫出 ROS 2 除錯順序與 transfer engine 四拍。

這些材料的用途是熟悉考試前會遇到的工具與背景概念，並不是考題本身；先做到能觀察、能解釋、能修改一兩個小地方，再進一步讀官方文件或 ISA/PIO 資料會比較有效。
