## 這次「改了沒生效」發生什麼

原本有兩份 demo：

```text
ncku-practice/demo           → 舊資料，Docker 原本掛這份
ncku-srecruit-practice/demo  → GitHub 專案，nvim 修改這份
```

檢查時，舊份 processor 仍是 `* 2`，新版是 `* 3 + 1`。所以重啟 Python，依然會讀到舊份。

已重新建立 srecruit-demo，將 GitHub 專案的 demo 掛到 /demo；當時實測送入 21，收到 64。舊 container 保留為 `srecruit-demo-before-path-fix-ae8613888852`，平常不需啟動它。

## Docker 只先理解三件事

- **Image**：裝好環境與依賴的模板。
- **Container**：依模板啟動的執行環境。
- **Bind mount**：同一份主機檔案，從 container 的另一個路徑讀寫。

因此：在主機 cd 到別處，不會改變 container 的掛載。掛載正確時，外面存檔、裡面便能讀到；已經啟動的 Python 程式仍要重新執行。

## 同步 GitHub

在主機專案資料夾執行：

```bash
cd ~/Development/ncku-srecruit-practice
git pull --ff-only
```

修改已掛載的 Python 原始檔後，存檔並重啟該程式即可；不需為每次修改重建 image。修改 Dockerfile 或安裝依賴的設定時，才需要考慮重新建置環境。

[Docker 官方掛載說明](https://docs.docker.com/engine/storage/bind-mounts/)
