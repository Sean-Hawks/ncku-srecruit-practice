## 練過例題後，用這五題檢查

每題先用自己的話解釋；說不清楚就回到對應例題畫資料。

1. `0xD6` 的高四位是多少？如何改成 3，保留低四位？
2. `/double` 沒輸出，你下一條查什麼？想排除什麼？
3. `out x, 32` 的來源與目的各是誰？
4. 兩個 thread 都做一次加一，為什麼最後可能只加了一？
5. 100 個 `uint32_t`，是幾筆、每筆幾 bytes？

每題記 0＝說不清、1＝看筆記能做、2＝能自己做並驗證。優先補 0 分項目。

## 位元與指標的實作題

另開練習檔，先預測再執行：

- 將 `0xD6` 的高四位改成 3，檢查低四位不變。
- 將 `{0x12,0x34,0x56,0x78}` 按第一個 byte 放最高位打包，再拆回來。
- 比較陣列與指標的 `sizeof`；解釋 `uint32_t *p` 的 `p+1` 前進幾 bytes。
- 測試全零、全一、最低位與最高位。

## 三題限時模擬

每題先自己分析 5 分鐘，再查靜態筆記、官方文件或用允許的本地模型。

1. **位元：**把 `0xA5` 的 bits 5..2 改成 3，保留其他位元。
2. **ROS：**改為 `y=2*x-1`，驗證輸入 `-3、0、7`；再故意接錯 topic 並定位。
3. **系統：**設定 64 筆 16-bit 填值並驗證；畫出兩個 thread 更新共享 counter 的鎖範圍。

## 筆記怎麼更新
