## 二、考場規則的實際含義

- 必須使用考場提供的桌上型電腦作答。
- 考場電腦可以上網；一般線上服務可以使用，也可以登入自己的帳號、開啟雲端硬碟裡的筆記。
- Gmail、LINE、Discord 等通訊軟體或服務仍然禁止使用；不能和任何人聯絡或傳遞資料。雲端硬碟只能拿來讀自己的參考資料，不能用通訊功能交換資訊。
- 考場提供一個部署在本地的網頁聊天模型。模型名稱不公開、不收費，但不提供檔案上傳；對話長度與單次貼上的程式碼長度有限制。
- 除了考場提供的模型以外，ChatGPT、Claude、Gemini、其他聊天機器人、AI Agent、GitHub Copilot 等一律不能使用；搜尋引擎的 AI 摘要也不能使用。
- 可以帶紙本筆記和書籍；考場不提供離線文件，需要查 RP2350、Pico SDK、ROS 2 等資料時，用考場電腦上網查官方文件。
- 只能用試場電腦已安裝的軟體，不得自行安裝軟體或外掛。
- 可以自帶鍵盤、滑鼠，但若聲音或其他因素影響他人，必須立即停止使用。
- 不得與其他考生交談，也不得以任何方式和考生以外的人通訊。手機、穿戴式裝置等應按試場安排收妥並保持不發聲。
- 考試期間禁止使用任何個人裝置；不要把手機、平板或自己的電腦當成備援查詢設備。
- Online Judge 評分；不要同時送出多份作答。看到一次提交尚未完成時，不要連續重按提交。
- 不得以阻斷式攻擊或其他方式干擾評分系統；公告寫明可能不計分並追究刑責。

成大通用試場規定另要求：依座號入座並核對資料；考試開始前不得翻閱題目或作答；一般規定中，開始 30 分鐘後不得入場、開始 40 分鐘內不得離場；違反攜帶物品、交談、抄襲、離場後修改答案、時間到仍作答等規定，都可能扣分或該科不予計分。這些規定會在不與資工系上機公告衝突的範圍內準用。

## 三、你最可能遇到的問題

### 1. 帳號或 GitLab 登入失敗

這是 11/13 試前測試最需要先排除的問題。應在 19:00 一開始就登入，依測試頁面要求確認帳號、指定專案或測試頁面能正常開啟；如果頁面要求下載、編譯或提交，再照頁面完成。公開公告只明文要求「登入 GitLab 進行測試」，不要自行把未公布的流程當成硬性規則。遇到問題先截圖記錄時間與錯誤訊息，再寄信給系上。

### 2. 不能安裝自己習慣的工具

考場不允許自行安裝軟體或外掛，所以不要把準備建立在某個 IDE、套件或 Python library 一定存在。練習時先用終端機、編譯器、`make`、Git 與瀏覽器完成工作；GitLab 建議至少會登入、找到專案、閱讀檔案，並在測試頁面要求時完成下載或提交。GitHub 沒有出現在目前這次考試的公告中，不需要為了考試另外建立 GitHub 專案。

### 3. 把「可以上網」誤解成「可以問外部 AI」

這封統一回覆明確把大型語言模型、AI Agent、Copilot 和搜尋引擎 AI 摘要排除在一般網路服務之外。考場只能用指定的本地模型；不要開 ChatGPT、Claude、Gemini、Copilot 或其他外部模型，也不要用手機代問。雲端筆記可以讀，但 Gmail 等通訊服務不能開。

### 4. 把「可以登入個人帳號」誤解成「可以用 Gmail」

系上信件同時說明：可以登入個人帳號、開啟雲端硬碟筆記，但考試期間禁止 Gmail、LINE、Discord 等通訊服務。準備時把需要的內容整理成雲端硬碟中的筆記或紙本；不要依賴寄信給自己、從信件找答案或請別人即時協助。

### 5. 只追求功能正確，忘了效能與量測

官方考試要點是閱讀特定系統軟硬體架構，以及運用工程知識優化程式和整體系統效能。練習時要養成先建立正確基準，再比較執行時間、CPU 使用率、記憶體與輸出結果的習慣。題目未必是一般演算法題，也不應假設附檔的 ROS 2、PIO、pthread 範例會原樣出現。

### 6. Online Judge 提交時機不對

先在本機或測試指令確認編譯、基本輸出與邊界條件，再提交。一次提交後等結果，不要同時開多個提交或重複按送出。若結果不對，先看編譯錯誤、執行逾時、記憶體問題和輸入輸出格式，再改下一版。

### 7. 長時間考試造成節奏失控

正式流程最晚可能到 19:30，而且午餐期間不能離開系館。建議上午先完成「讀懂介面、跑通基準版本、確認提交流程」，下午再做優化和整理說明；不要把第一個可運作版本拖到下午才完成。

## 四、從附檔練習材料應該練什麼

附檔 README/PDF 明確說明它們是背景練習，不是正式考題。最值得轉移到正式考試的能力是：

- 看文件找出資料流、介面、限制與錯誤條件。
- 能用終端機和觀察工具定位問題，而不是先亂改程式。
- 位元遮罩、移位、欄位抽取與資料打包。
- 多執行緒共享資料的競爭條件、鎖的範圍與效能代價。
- 以 configure → start → wait/busy → 使用結果 的方式操作資料搬運類介面。
- 分清楚 `count` 的單位、位址是否遞增、資料寬度與對齊限制。
