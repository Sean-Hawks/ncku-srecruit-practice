## 最常忘的規則

| 主題 | 直接查 |
|---|---|
| RV32I 欄位 | opcode=`w&0x7F`；rd=`(w>>7)&31`；funct3=`(w>>12)&7`；rs1=`(w>>15)&31`；rs2=`(w>>20)&31`；funct7=`(w>>25)&127` |
| 有號立即數 | I 格式取 bits31..20；12-bit 的0xFFC代表 -4，branch／store 另查格式 |
| 位址 vs 內容 | addi 只加值；lw 算 byte 位址後讀4 bytes；x0 固定為0 |
| 取欄位 | `(x >> shift) & low_mask` |
| 換欄位 | `mask=low_mask<<shift; x=(x&~mask)\|((value<<shift)&mask)` |
| 位元限制 | 用無號型別，32-bit 值不能移32位；~會翻轉整個型別的 bits |
| PIO 路徑 | CPU→TX FIFO→OSR→X→ISR→RX FIFO→CPU；out／in／push 對應中間三步 |
| FIFO 等待 | 輸入沒資料、輸出沒空間都可能等；push 不等於 CPU 已讀取 |
| ROS | node 是執行單位、topic 是通道；echo 只接收；/double 名稱不決定算法 |
| 共享資料 | 鎖保護完整讀改寫；volatile 不等於 atomic／同步 |
| buffer | queue 傳指標不複製內容；worker／DMA 用完前不能重用 |
| 搬運 | 總 bytes=count×每筆 bytes；複製兩端遞增，填值來源固定 |
| count vs memcpy | DMA／演練 count 是筆數；memcpy 第三參數是 bytes |
| 校驗 | CRC 要核對版本、初值、反射、最後 XOR、資料範圍；完成後讀 sniffer |
| 多板 | 按 job_id 對回輸入，不能把分類編號相加 |
| 改了沒變 | 存檔→確認同一份→重新建置→重啟／寫入板子 |
| 慢在哪 | 量整條路各段，非同步工作等完成才停表 |

本 repo 的 processor 是3*x+1（21→64）、搬運 N=8；官方原式2*x（21→42）、N=4096。

## 卡住時的順序

**收到輸入 → 解析 → 計算／分派 → 等完成 → 包裝 → 回傳。** 每段查型別、數量、單位、誰讀寫。固定錯先查規格，偶爾錯先查越界／同步／buffer。

## 考場本地模型提問模板

模型不會知道這份對話；只貼有關函式與宣告，一次問一件事：

```text
環境／版本：
題目明確規格（輸入、輸出、長度單位）：
相關函式與型別宣告：
預期結果：
實際錯誤／結果：

請先追資料從哪裡到哪裡，指出錯誤的那一行。
若資訊不足請列出，不猜板型、API 或封包格式。
需要修改時，說明修改前後的結果和驗證方法。
```

ISA 問「欄位在哪、正負怎麼解、PC 怎麼走」；PIO 問「每行讀寫哪裡、何時等待」；平行問「誰讀寫同一份資料、buffer 何時可重用」；DMA 問「筆數、寬度、總 bytes 是否一致」。

模型答案以題目、實際函式宣告與官方手冊核對。[考場規則](成大上機考規則與避雷.md)
