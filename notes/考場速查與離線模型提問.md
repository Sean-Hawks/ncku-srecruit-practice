# 考場速查與離線模型提問

頁內搜尋：`ROS、mask、byte、鎖、count、PIO、模型`。

## ROS 資料在哪一段斷掉

| 要證明的事 | 指令 |
|---|---|
| node 有啟動 | `ros2 node list` |
| topic 名稱與型別 | `ros2 topic list -t` |
| processor 接到哪裡 | `ros2 node info /processor` |
| 有發送與接收端 | `ros2 topic info /number` |
| 訊息欄位 | `ros2 interface show std_msgs/msg/Int32` |
| 輸入／輸出真的有資料 | `ros2 topic echo /number`、`ros2 topic echo /double` |
| 觀察到的輸入頻率 | `ros2 topic hz /number` |

`echo、hz` 持續執行；Ctrl-C 結束或另開終端機。`echo` 也會增加訂閱者。

停掉隨機 publisher，保留 processor；另一個終端機先觀察輸出，再注入：

```bash
ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"
```

原版應輸出 42。名稱、型別都對仍不通，再查 QoS、`ROS_DOMAIN_ID` 與各 shell 的環境。


pthread 加 `-pthread`；原 demo 用既有 Makefile。正式題目先用指定建置方式。先處理第一個編譯錯誤，再用最小輸入定位；除錯文字別混進要求固定格式的輸出。

## mask 先清再填

需 `<stdint.h>`；以下使用 `uint32_t`。

```c
/* 0 <= n < 32 */
x |= UINT32_C(1) << n;       /* 設 1 */
x &= ~(UINT32_C(1) << n);    /* 清 0 */
x ^= UINT32_C(1) << n;       /* 反轉 */
uint32_t bit = (x >> n) & UINT32_C(1);

/* 1 <= width <= 31，0 <= lo，lo + width <= 32 */
uint32_t low = (UINT32_C(1) << width) - UINT32_C(1);
uint32_t field = (x >> lo) & low;
uint32_t mask = low << lo;
uint32_t changed = (x & ~mask) | ((value & low) << lo);
```

右移後遮罩＝抽取；清空後 OR＝替換。此寫法會截掉 value 超出的位元；規格不允許就先檢查範圍。

寬度 32 直接使用整個 `x` 或 `value`，別 shift 32。驗證欄位外不變：`(changed & ~mask) == (x & ~mask)`。

## byte 明確指定順序

`b` 是至少四個元素的 `uint8_t` 陣列，第一個 byte 放最高位：

```c
uint32_t word = ((uint32_t)b[0] << 24)
              | ((uint32_t)b[1] << 16)
              | ((uint32_t)b[2] << 8)
              | (uint32_t)b[3];
uint8_t high = (uint8_t)(word >> 24);
uint8_t low = (uint8_t)(word & UINT32_C(0xFF));
```

先轉型再移位。`{0x12,0x34,0x56,0x78}` 得到 `0x12345678`。指標的 `sizeof` 不等於陣列長度。

## 鎖保護完整讀改寫

```text
獨立計算 → lock → 讀共享值／更新／寫回 → unlock
```

逐一找出共享物件；`volatile` 不提供同步。原 demo 的短鎖 `sink` 與引擎 `busy` 另有 data race，不能照抄為安全同步寫法。

比較效能前，先確認同樣輸入得到同樣結果，再多次量測。

## count 是筆數

```text
總 bytes = count × 每筆 bytes
claim → configure → start → wait → 驗證 → release
```

本 demo 的 `engine.h` 設定：

| 工作 | count | size | src_increment | dst_increment |
|---|---:|---|---|---|
| 複製 100 個 uint32_t | 100 | XFER_32 | true | true |
| 用 uint32_t pattern 填 100 筆 | 100 | XFER_32 | false | true |
| 用 uint16_t pattern 填 64 筆 | 64 | XFER_16 | false | true |

填值的來源指向單一 pattern；目的陣列要夠大、位址要對齊、buffer 要活到工作完成。`engine_claim()` 回傳負值時先處理無通道情況。

啟動成功不等於完成。真實 DMA 改用對應 SDK，確認筆數編碼。

## PIO 追資料

```text
TX FIFO → OSR → out → X → in → ISR → push → RX FIFO
```

Demo 假設 autopull 設好。逐步問：從哪裡、到哪裡、幾 bits、會不會等？實作再查移位方向、threshold 與 autopush。CPU 與 PIO 指令分開看。

## 模型 一次只問一個問題

依現有規則筆記，現場模型不能上傳檔案，貼上與對話長度有限。複製下面模板：

```text
環境／版本：
目標與限制：
相關函式／必要型別：
最小輸入：
預期：
實際輸出或原始錯誤：
已排除：

請先指出可能原因與檢查方式，再給最小修改，
附正常與邊界測試。不確定的 API 請明說。
```

概念卡住就問：「用這段實際變數畫資料流或 thread 時序，先不要改碼。」

自己查官方函式簽章再貼給模型；回答要經過編譯與測試。新對話重貼關鍵背景。
