# 位元運算：取出、修改與組合欄位

[← 回考場筆記入口](../README.md) · [指令欄位](ISA與指令編碼.md)

## 第一性原理：整數是 bits 的組合，欄位由規格賦予意義

在無號 W-bit 整數中，每個 bit 只取 0 或 1，第 i 位對數值的貢獻是 `bit[i] × 2^i`。同一串 bits 可以被當成一個數，也可以依規格切成旗標、欄位或多個小整數。**要操作其中一段，就先用移位把位置對齊，再用遮罩決定哪些 bits 保留。**

右移 s 位讓原本從第 s 位開始的欄位移到最低位；與低 w 位為 1 的 mask 做 AND，就只留下這 w 位。替換欄位時，必須先清掉舊 bits，再 OR 進新值；單做 OR 無法把原本的 1 改成 0。這些公式都來自每一位的真假規則。

### 要解決什麼問題

在有限寬度的指令、暫存器或封包中，精確讀寫某些欄位，同時保留其他欄位。例如指令解碼取 opcode、封包拆兩個 byte、只改一個控制旗標，都能用同一套方法。C 的實際型別與移位限制另依 [C11 N1570 §6.5.7、§6.5.10–12](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。

### 上機考可能怎麼出現

- **演練已出現：**[demo_asm.c](../../demo/section2-2/demo_asm.c) 示範 AND／OR／XOR／NOT、移位、設定／清除／取出位元。
- **可能任務（推測）：**依欄位圖拆包、修改特定位元、組回機器碼，或把數個欄位打包成回傳值。看到 `mask`、`shift`、`bits 15..8` 就先圈出欄位起點與寬度。
- **具體例子：**若規格定義 `0x0305` 的高、低 byte 是 A、B，則 `A=(x>>8)&0xFF` 得 3、`B=x&0xFF` 得 5；若要求 A+B，回傳才是 8。拆欄位與後續算法分兩步做。
- **動手順序：**標位寬／位置 → 選無號型別 → 移位與遮罩 → 用全 0、全 1、邊界值核對，最後查 byte 順序與有號解讀。

---

**一個整數可以裝很多個欄位；規格用 bit 位置分隔它們。** bit 從右邊的 0 開始，mask 裡的 1 表示選到該位置。

```text
0xA5 = 1010 0101
位置    7654 3210
```

## 公式直接查

假設 x 是 uint32_t，0≤n<32；欄位完全落在 32 bits 內。

| 目的 | 寫法 | x=0xA5 的答案 |
|---|---|---|
| AND：兩邊都 1 才留 1 | `x & 0x0Fu` | 0x05 |
| OR：任一邊 1 就為 1 | `x \| 0x0Fu` | 0xAF |
| XOR：兩邊不同才為 1 | `x ^ 0x0Fu` | 0xAA |
| NOT：翻轉，只看低 8 bits | `(~x) & 0xFFu` | 0x5A |
| 取高四位並移到最低位 | `(x >> 4) & 0xFu` | 10，即 0xA |
| 設 bit n | `x \|= 1u << n` | n=1 → 0xA7 |
| 清 bit n | `x &= ~(1u << n)` | n=2 → 0xA1 |
| 翻 bit n | `x ^= 1u << n` | n=0 → 0xA4 |
| 查 bit n | `(x >> n) & 1u` | n=2 → 1 |

`x & mask` 只算結果；`x &= mask` 才寫回 x。`~` 會翻轉型別的所有 bits，uint32_t 的 `~0xA5u` 不是只有 0x5A。

## 任意欄位：右移、遮罩；替換先清再填

以 bits 5..2 為例：寬 4 bits、起點 2、低位 mask=0xF。

```c
uint32_t field = (x >> 2) & 0xFu;
uint32_t mask = 0xFu << 2;       // 0x3C
x = (x & ~mask) | ((value << 2) & mask);
```

`x & ~mask` 清掉舊欄位；`(value << 2) & mask` 只放新欄位；OR 合併兩者。value 也應是無號型別。

| 已算好的例子 | 結果 |
|---|---|
| x=0xA5，bits 5..2 換成 3 | 0x8D |
| x=0xD6，高四位換成 3 | 0x36 |
| 錯用 `0xD6 \| (3u<<4)` | 0xF6，原欄位的 1 沒清掉 |

一般寬度 w 的低位遮罩是 `(1u<<w)-1u`，僅適用 1≤w<32。寬 32 時直接用 UINT32_MAX。

## 打包與拆包：數值和記憶體順序分開

規格若指定第一個 byte 放最高位：

```c
uint32_t v = ((uint32_t)b[0] << 24) | ((uint32_t)b[1] << 16)
           | ((uint32_t)b[2] << 8)  | (uint32_t)b[3];
// b={0x12,0x34,0x56,0x78} → v=0x12345678
uint32_t high = (v >> 24) & 0xFFu; // 0x12
uint32_t low  = v & 0xFFu;         // 0x78
```

這是在定義**數值如何組成**。Endianness 是這個多 byte 數值在記憶體／封包裡如何排列；v=0x12345678 在 little-endian 記憶體是 `78 56 34 12`。詳見 [封包](平行運算.md#封包與多板交接)。

Python 也能取欄位：`(packed >> 8) & 0xFF`、`packed & 0xFF`；例如 0x0305 拆出 3 和 5。Python 整數不限 32 bits，模擬固定寬度時要按規格加 mask。

## 常見錯誤

| 問題 | 原因／正確理解 |
|---|---|
| `&` 寫成 `&&` | 前者逐 bit AND；後者判斷真假 |
| `x & mask == value` | 優先序不合預期，寫 `(x & mask) == value` |
| `1u << 32` | 對 32-bit 無號值，移位量必須小於 32 |
| byte 直接 `<<24` | 先轉 uint32_t，避免整數提升成 signed int 後出問題 |
| 負數、溢位混進欄位運算 | 用明確無號型別；有號立即數另做符號延伸 |
| `%X` 當成轉型 | 它只改顯示方式，數值本身不變 |
