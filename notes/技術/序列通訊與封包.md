# 序列通訊與封包：電腦、板子如何約好格式

**串口送的是 bytes。接收端必須知道每筆從哪裡開始、長度多少、各欄位怎麼解讀。** 一次 read 不保證剛好一個完整封包。

ROS topic 也有訊息格式，但 USB/UART 的傳輸方式要依題目橋接程式；不是板子插上去就自動成為 ROS node。

## 文字與 binary 差在哪

| 想傳數字 21 | bytes |
|---|---|
| 文字 `"21\n"` | 0x32 0x31 0x0A |
| uint32 little-endian | 0x15 0x00 0x00 0x00 |

binary 在大量數值／陣列時可減少文字轉換與體積，但**不保證每個小數字都更短**。文字與 binary 兩端要用同一套，不能只改發送端。

## 不用板子也能練：打包與拆包

規格：兩個 unsigned 32-bit 整數，第一個 request ID、第二個 value，little-endian。存成 `packet_check.py`：

```python
import struct

packet = struct.pack("<II", 7, 21)  # < 小端序，I 固定 4 bytes
assert len(packet) == 8
assert packet.hex(" ") == "07 00 00 00 15 00 00 00"
request_id, value = struct.unpack("<II", packet)
assert (request_id, value) == (7, 21)
print(packet.hex(" "))
print(f"id={request_id} value={value}")
```

```bash
python3 packet_check.py
```

預期 `07 00 00 00 15 00 00 00`、`id=7 value=21`。改成 `>II` 是大端序，收送都必須配套；固定 `<`／`>` 也避免用到 native padding。

## 串口：工具已提供、有板子才做

在**連著板子的主機**：

```bash
ls /dev/serial/by-id/
ls /dev/ttyUSB* /dev/ttyACM*
```

若有預裝 pySerial：

```bash
python3 -m serial.tools.list_ports
python3 -m serial.tools.miniterm /dev/ttyUSB0 115200
```

把 port 與 baud 換成實際值。miniterm 退出是 Ctrl+]；不要同時讓自己兩個程式搶同一串口。容器還可能需要 USB 映射，見 [Docker](Docker.md)。

<details>
<summary>固定長度協定：如何累積收到完整封包</summary>

以下是**需要 pySerial 與相符板子韌體的完整主機範例**。板子必須接受上面的 8-byte 請求、回相同格式；這不是通用 ESP32／PIO 協定。

```python
import struct
import time
import serial

def read_exact(port, size, seconds=2.0):
    deadline = time.monotonic() + seconds
    data = bytearray()
    while len(data) < size:
        if time.monotonic() >= deadline:
            raise TimeoutError(f"only received {len(data)}/{size} bytes")
        data.extend(port.read(size - len(data)))
    return bytes(data)

with serial.Serial("/dev/ttyUSB0", 115200, timeout=0.1, write_timeout=2) as port:
    # 若開串口會重啟板子，這裡先依題目協定等 ready，再發請求。
    request = struct.pack("<II", 7, 21)
    if port.write(request) != len(request):
        raise IOError("short write")
    reply = read_exact(port, 8)
    request_id, answer = struct.unpack("<II", reply)
    if request_id != 7:
        raise ValueError("unexpected request id")
    print(request_id, answer)
```

read_exact 解決分次到達；**不解決失去封包邊界**。若韌體混入啟動文字或中途掉 byte，還需題目指定的 header、length、校驗與重新同步機制。

</details>

## 多板／平行處理必備

- request ID：哪一筆輸入的答案，不能只看回來順序。
- length：這筆 payload 有幾 bytes，不是幾個 uint32_t。
- endian：例如 0x12345678 是 `78 56 34 12` 還是 `12 34 56 78`。
- 正式資料和 debug log 分開；同一串 binary 裡混入 printf 會破壞解析。
- 超時後是否重送、重複 ID 如何處理，依題目協定。
