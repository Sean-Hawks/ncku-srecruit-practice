## ESP32 與你熟悉的 PlatformIO

ESP32 是晶片系列；PlatformIO 是建置／上傳／監看工具。`pio` CLI 與 RP2350 的 PIO 硬體不同。板型決定 ISA、核心數與功能，不能全當雙核心。

| 專案線索 | 建置 | 寫入指定裝置 | 入口 |
|---|---|---|---|
| platformio.ini | `pio run -e "<env>"` | `pio run -e "<env>" -t upload --upload-port "<port>"` | src/，依 framework |
| ESP-IDF 的 CMake／sdkconfig | `idf.py build` | `idf.py -p "<port>" flash` | app_main |
| Arduino .ino | IDE 的 Verify | 選對 Board／Port 後 Upload | setup／loop |

`<...>` 換成實際值，使用題目提供的工具。ESP-IDF monitor 是 `idf.py -p "<port>" monitor`，Ctrl+] 離開；PlatformIO 用 `pio device monitor -p "<port>" -b "<baud>"`。

FreeRTOS task 可分收送與計算；共享資料用 queue／mutex 等同步。跨核心只關本核心中斷不足以保護另一核心。[工作交接與多板](平行運算.md#封包與多板交接)

## eBNN：接上提供的模型

eBNN 是針對小型裝置的二值神經網路方案。推論是用已訓練的模型算預測；若題目模型已給，不需因此重做訓練。

解題路徑：**收資料 → 轉成模型要求的格式 → 呼叫推論 → 回類別／分數**。

| 必查 | 不能猜的差異 |
|---|---|
| 函式宣告／例子 | 輸入參數、輸出大小與型別 |
| 輸入與前處理 | float、原始 bytes、打包 bits 不同；正規化與順序依模型 |
| 中間暫存區 | 共用可變狀態可能使多核心同時推論算錯 |
| 標準答案 | 分類編號與分數向量是不同輸出 |

784 個4-byte float 是3136 bytes；784 個1-bit 值是98 bytes，**但只有模型／協定支援時才能這樣改**。

二值比較的直覺：`~(a ^ b) & mask` 留下相同的位置，popcount 數1的個數。若每 bit 代表同一套 ±1 編碼，內積＝2×相同數−總位數；尾端填補 bits 需遮掉。完整模型仍有層與閾值。

多板優先分不同樣本，各附 job_id；分類結果依 ID 排回，不把類別編號相加。

## 如果出排序、SHA、CRC

排序要看型別／方向；SHA-0、SHA-1、SHA-256 是不同演算法；CRC32 還要看參數。你提供的心得提醒 README 與 PDF 曾不同，遇到差異要查當年正式規格／勘誤，不能套用歷屆版本。
