# 歷屆備查：ESP32／eBNN

[← 回考場入口](../README.md)

## 第一性原理：小型裝置的算力、RAM 與通訊都有成本

這頁包含數種歷屆技術，先分別理解它們面對的限制：

- **ESP32／開發工具：**運算要由實際 CPU 執行，周邊要依晶片介面操作；ESP32 提供硬體，ESP-IDF／Arduino 提供程式介面，PlatformIO 管理建置等流程。原始碼仍要經目標工具鏈編譯、寫入，才成為板子正在執行的程式。
- **FreeRTOS task：**收訊和計算可能需要不同等待方式，所以拆成可排程的工作，透過 queue／同步機制交接。task 多於一個不等於真的有多顆核心，能否同時執行要看晶片與設定。
- **eBNN：**神經網路的權重與中間結果都占 RAM；若以二值表示適用的資料，就能打包多個值，並利用位元操作。eBNN 還安排推論計算與暫存方式來降低中間結果的記憶體需求。這必須符合既有模型，不能自行把任何 float 輸入直接壓成 bits。[eBNN 原專案](https://github.com/kunglab/ebnn) 說明其記憶體目標與推論介面。
- **排序／SHA／CRC：**排序要建立指定的元素次序；SHA 將資料算成密碼學摘要，CRC 依指定規則累積校驗值。它們解決的問題與輸出不同，不能只因都是「處理一批 bytes」就交換使用。

### 要解決什麼問題

在有限資源下，完成收資料、運算與回傳。先分清限制在模型暫存、CPU 計算、排程還是傳輸，才能選擇減少複製、位元打包或獨立樣本分工。ESP32／工具的能力依本頁末尾官方文件與現場版本確認。

### 上機考可能怎麼出現

**以下全是歷屆方向的推測；本 repo 的歷屆筆記未附原始考題可供核對，也不能據此確認今年使用這些技術。**

- **ESP32／task：**可能要求在既有 `app_main` 或 callback 接上計算，將收送與耗時工作分開；先查現場板型、API 與資料交接方式。
- **eBNN：**可能提供模型與推論函式，要求補前處理、批次推論或分派樣本。例如收到一張樣本後轉成模型格式，呼叫推論，再按工作 ID 回傳類別；模型已給時先把這條路接對。
- **排序／SHA／CRC：**可能給輸入陣列或 byte buffer，要求指定順序／指定版本的結果。先讀元素型別、長度單位、算法版本與標準測資，再談加速。
- **共同動手順序：**讀函式宣告與 I/O 規格 → 跑通單筆正確結果 → 檢查暫存區能否同時使用 → 最後才批次化或多核心／多板分工。

## ESP32 與你熟悉的 PlatformIO

ESP32 是晶片系列；PlatformIO 是建置／上傳／監看工具。`pio` CLI 與 RP2350 的 PIO 硬體不同。板型決定 ISA、核心數與功能，不能全當雙核心。

| 專案線索 | 建置 | 寫入指定裝置 | 入口 |
|---|---|---|---|
| platformio.ini | `pio run -e "<env>"` | `pio run -e "<env>" -t upload --upload-port "<port>"` | src/，依 framework |
| ESP-IDF 的 CMake／sdkconfig | `idf.py build` | `idf.py -p "<port>" flash` | app_main |
| Arduino .ino | IDE 的 Verify | 選對 Board／Port 後 Upload | setup／loop |

`<...>` 換成實際值，使用題目提供的工具。ESP-IDF monitor 是 `idf.py -p "<port>" monitor`，Ctrl+] 離開；PlatformIO 用 `pio device monitor -p "<port>" -b "<baud>"`。

FreeRTOS task 可分收送與計算；共享資料用 queue／mutex 等同步。跨核心只關本核心中斷不足以保護另一核心。[工作交接與多板](平行運算.md#封包與多板交接)

## eBNN：接上提供的模型

eBNN 是針對小型裝置的二值神經網路方案。推論是用已訓練的模型算預測；若題目模型已給，不需因此重做訓練。

解題路徑：**收資料 → 轉成模型要求的格式 → 呼叫推論 → 回類別／分數**。

| 必查 | 不能猜的差異 |
|---|---|
| 函式宣告／例子 | 輸入參數、輸出大小與型別 |
| 輸入與前處理 | float、原始 bytes、打包 bits 不同；正規化與順序依模型 |
| 中間暫存區 | 共用可變狀態可能使多核心同時推論算錯 |
| 標準答案 | 分類編號與分數向量是不同輸出 |

784 個4-byte float 是3136 bytes；784 個1-bit 值是98 bytes，**但只有模型／協定支援時才能這樣改**。

二值比較的直覺：`~(a ^ b) & mask` 留下相同的位置，popcount 數1的個數。若每 bit 代表同一套 ±1 編碼，內積＝2×相同數−總位數；尾端填補 bits 需遮掉。完整模型仍有層與閾值。

多板優先分不同樣本，各附 job_id；分類結果依 ID 排回，不把類別編號相加。

## 如果出排序、SHA、CRC

排序要看型別／方向；SHA-0、SHA-1、SHA-256 是不同演算法；CRC32 還要看參數。你提供的心得提醒 README 與 PDF 曾不同，遇到差異要查當年正式規格／勘誤，不能套用歷屆版本。
