# 平行運算：分工、共享資料與等待

[← 回考場筆記入口](../README.md) · [效能量測](效能量測與除錯.md)

**增加執行者之前，先分清每份資料由誰讀寫。** 同時做互不干擾的工作才有機會加速；搶同一份資料會需要同步。

## 名詞查表

| 名詞 | 意思 |
|---|---|
| process | 執行中的程式，通常有自己的位址空間 |
| thread | 同一程序中的執行路徑，可共用記憶體 |
| core | 真正執行 CPU 指令的硬體核心 |
| mutex | 互斥鎖，同一時間只讓持有者進入保護區 |
| spinlock | 自旋鎖，拿不到鎖時反覆檢查，等待期間仍占 CPU |
| critical section | 存取共享狀態、必須保護的一段操作 |
| join | 等指定 thread 結束 |
| atomic | 提供不可被拆開觀察的操作，另有記憶體順序規則 |

有兩條 thread 不代表有兩顆核心，也不保證速度加倍。

## 為什麼 counter++ 需要保護

概念上，`counter++` 包含「讀 → 加一 → 寫回」。兩個人可能交錯：

```text
A 讀 0 → B 讀 0 → A 寫 1 → B 寫 1
```

兩次加一卻只留下 1，叫 lost update。這是理解用的時序；在 C 中，未同步的衝突讀寫構成 data race，屬未定義行為，不能保證只少幾次。

```c
pthread_mutex_lock(&lock);
++counter;                         // 共享值的完整更新
pthread_mutex_unlock(&lock);
```

上面是 mutex 的示意片段。官方演練實際使用 **pthread spinlock**，對應的是 `pthread_spin_lock(&lock)`／`pthread_spin_unlock(&lock)`；型別與初始化也必須成套，不能只換函式名稱。

只鎖最後的寫入仍可能用到過期值。`volatile` 只涉及編譯器對存取的處理，**不提供原子加一或 thread 同步**。

## 鎖放哪，結果會如何

| 寫法 | 結果／代價 |
|---|---|
| 共享更新沒同步 | 資料競爭，結果不可靠 |
| 只鎖完整共享更新 | 可保護該狀態，其他獨立計算能並行 |
| 把耗時獨立計算也放進同一把鎖 | 其他 thread 被迫等待，可能失去加速 |
| 每個 worker 用自己的累積值，join 後合併 | 減少共享更新，常適合獨立分塊 |

移到鎖外的計算若仍讀寫共享狀態，就不能假設安全。鎖要保護所有相關不變條件；讀取結果的一端也要遵守同步規則。

## pthread API 與執行順序

```text
準備各自參數 → pthread_create → worker 計算 → pthread_join → 合併結果
```

| API | 用途／注意 |
|---|---|
| `pthread_create(&tid, NULL, worker, &args)` | 建 thread；args 要活到 worker 用完，不能反覆傳同一個會改的 loop 變數 |
| `pthread_join(tid, NULL)` | 等它完成，再讀它寫出的結果 |
| `pthread_mutex_init`／`destroy` | 初始化／用完銷毀鎖，也可用靜態初始化 |
| `pthread_mutex_lock`／`unlock` | 保護共享操作，避免漏解鎖或互相等鎖 |
| `pthread_spin_init(&lock, PTHREAD_PROCESS_PRIVATE)` | 初始化演練使用的自旋鎖，型別為 pthread_spinlock_t |
| `pthread_spin_lock`／`unlock`／`destroy` | 自旋取得、釋放、用完銷毀 |

mutex 在等待時可讓 thread 阻塞；spinlock 持續占 CPU 等待，尤其不適合包住長時間工作。兩者都要在使用前初始化，並在所有使用者結束後才銷毀。

Linux 編譯通常加 `-pthread`。這是 pthread API；Pico SDK 雙核心與 ESP-IDF／FreeRTOS task 各有自己的 API。

## 一批工作怎麼分

N 筆獨立資料給 P 個 worker，可讓第 k 個處理半開區間：

```text
start = N*k/P
end   = N*(k+1)/P
處理 start ≤ i < end
```

例如 N=5、P=2：worker 0 處理 [0,2)，worker 1 處理 [2,5)。每筆只出現一次，合計 5 筆。實作要避免乘法溢位，並處理空區間。

- 工作耗時相近：固定切塊容易管理。
- 工作耗時差很多：做完再從工作佇列領下一份，可減少慢的一方拖累。
- 多板：記憶體分開，工作與結果要經通訊傳輸，以 job_id 對回原輸入。
- 同板雙核心：可以共用 RAM，但 queue、buffer 所有權和模型暫存區仍需同步。

## 為什麼分工反而慢

總時間含 **分派、傳輸、計算、等待、合併**。能平行的比例有限：若只有比例 p 可平行，P 個執行者的理想加速上限為 `1 / ((1-p)+p/P)`，實際還有額外成本。

## 官方演練程式的適用範圍

[critical-section/main.c](../../demo/section2-3/critical-section/main.c) 用 counter 比較鎖範圍。原碼另有未同步的共享 sink 更新，不能因 counter 加鎖就稱整個程式安全。兩個 worker 各加 20000 次的預期 counter 是 40000；未加鎖版本的數值沒有保證。
