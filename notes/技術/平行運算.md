# 平行運算：分工、等完成、合併結果

多板完整情境：[RP2350／eBNN 從單板到多板](RP2350-eBNN從單板到多板.md)；沒有板子可先跑 [多個 C worker 練習](../../demo/first-development/parallel.py)。

**先把工作分成互不干擾的部分，再讓多個執行者做；讀結果前等它們完成。** 有多個 thread 不保證同時執行，也不保證比較快。

| 概念 | 意思 |
|---|---|
| process | 執行中的程式，通常有自己的位址空間 |
| thread | 同一 process 內的執行路徑，會共用記憶體 |
| core | 真正執行 CPU 指令的硬體核心 |
| task | 排程單位；在 FreeRTOS 中用來安排工作 |
| join | 等指定 thread 結束 |

## 先跑現有範例

在**容器**：

```bash
cd /demo/section2-3
make run-critical-section
```

看 [critical-section/main.c](../../demo/section2-3/critical-section/main.c)。兩個 worker 各做 20000 次，counter 應為 40000。

`counter++` 包含：讀舊值 → 加一 → 寫回。兩邊都讀到 0，各自寫回 1，就少算一次。

**C 裡未同步的共享讀寫是 data race，屬未定義行為。** 不只是「保證少幾次」。原 demo 還有共享 sink 的未保護寫入，因此鎖住 counter 不代表整份原 demo 已無 race。volatile 也不會修好。

## 鎖應該包什麼

```c
pthread_mutex_lock(&lock);
counter++;                       // 完整讀、改、寫都在同一把鎖裡
pthread_mutex_unlock(&lock);
```

lock 需先宣告／初始化，例如 `pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;`。所有會存取同一共享資料的 thread 都要遵守同一套同步規則。不要只鎖讀取、放開後才寫回。

- **mutex**：競爭時可讓等待者休眠，適合一般 thread 同步。
- **spinlock**：等待時反覆查鎖，適用很短且符合平台限制的區段。
- **atomic**：對共享變數做原子操作；例如 C11 `atomic_fetch_add(&counter, 1)`。counter 也必須宣告成對應 atomic 型別。
- **queue**：把工作或結果交給另一方，可減少直接共用可修改的資料。

## 可直接跑的實作：兩人各算一半，再合併

存成 `parallel_sum.c`。這題用不同結果格子，工作中不需要共同累加一個 counter。

```c
#include <assert.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    const int *data;
    size_t begin, end;             // [begin, end)：不包含 end
    long long result;
} Job;

static void *worker(void *arg) {
    Job *job = arg;
    long long sum = 0;             // 每條 thread 自己的區域變數
    for (size_t i = job->begin; i < job->end; ++i)
        sum += job->data[i];
    job->result = sum;             // 每個 worker 寫不同的 Job
    return NULL;
}

int main(void) {
    const int data[] = {1, 2, 3, 4, 5, 6, 7, 8};
    const size_t n = sizeof data / sizeof data[0];
    Job jobs[2] = {{data, 0, n / 2, 0}, {data, n / 2, n, 0}};
    pthread_t threads[2];
    for (int i = 0; i < 2; ++i) {
        int error = pthread_create(&threads[i], NULL, worker, &jobs[i]);
        if (error != 0) {
            fprintf(stderr, "pthread_create error=%d\n", error);
            exit(EXIT_FAILURE);
        }
    }
    for (int i = 0; i < 2; ++i) {
        int error = pthread_join(threads[i], NULL);
        if (error != 0) {
            fprintf(stderr, "pthread_join error=%d\n", error);
            exit(EXIT_FAILURE);
        }
    }
    long long answer = jobs[0].result + jobs[1].result;
    assert(answer == 36);
    printf("sum=%lld\n", answer);
}
```

```bash
cc -std=c11 -O2 -Wall -Wextra -pthread parallel_sum.c -o parallel_sum
./parallel_sum
```

預期 `sum=36`。把最後的 8 改成 80，預期 108，assert 一起改。奇數筆也可用相同切法；工作與資料生命週期都持續到 join 後。

## 多核心、多板的分工

```text
工作 0..49  → worker A → partial A ┐
                                  ├→ 等兩份結果 → 合併
工作 50..99 → worker B → partial B ┘
```

兩個板子可以不同步完成。傳送附 request ID、區段編號；按 ID 合併，不用回來的先後順序當原始順序。

若每件工作本來只花幾微秒，建立 thread、傳資料、等待可能更貴。短鎖避免把無關的慢工作全部包進去；但所有共享變數仍須保護。

## ESP32／Pico 不直接照抄 pthread

ESP-IDF 用 FreeRTOS task、mutex、queue；Pico SDK 有 multicore 與同步 API。概念相通，API 不同；先看題目平台。[ESP32](ESP32.md) · [Pico SDK](RP2350與PicoSDK.md)
