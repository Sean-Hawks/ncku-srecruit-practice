# C 記憶體與指標

[← 回考場筆記入口](../README.md) · [資料搬運](資料搬運.md)

**變數存值，指標存位址。指向同一份資料，與複製一份資料，是不同的事。**

## 最容易混的符號

| 寫法 | 意思 |
|---|---|
| `x` | x 的值 |
| `&x` | x 的位址 |
| `p` | 指標裡存的位址 |
| `*p` | p 指向的物件，可讀／寫其內容 |
| `p[i]` | 等同 `*(p+i)` |
| `p = src` | 只複製位址 |
| `memcpy(dst, src, bytes)` | 複製指定 bytes 的內容；區域不可重疊 |

memcpy 需要 `<string.h>`；重疊區域用 memmove。兩者都不會替你檢查目的容量。

## sizeof(uint32_t) 為什麼是 4

在本環境，1 byte=8 bits；uint32_t 是剛好 32 bits 的無號型別，因此 `sizeof(uint32_t)=4`。

```text
uint32_t a[3]，假設起點是位址 1000：
a[0]：1000..1003
a[1]：1004..1007
a[2]：1008..1011
```

`a+1` 前進一個元素，即 4 bytes；若改成 `uint8_t *p`，p+1 才是 1 byte。

| 表達式 | 本例答案 |
|---|---|
| `sizeof(a)` | 陣列總容量：3×4=12 bytes |
| `sizeof(a[0])` | 一個元素：4 bytes |
| `sizeof(a)/sizeof(a[0])` | 3 個元素；只適用仍是陣列的地方 |
| `sizeof(p)` | 指標本身的大小，看平台，不是資料長度 |

函式參數 `uint32_t a[]` 會調整成指標；在函式裡不能用 sizeof(a) 推回傳入陣列長度，必須另外傳 count。

## 指向同一份，改了會一起看到

```c
uint32_t src[2] = {10, 20};
uint32_t *p = src;          // p 與 src 指同一份資料
uint32_t dst[2];
memcpy(dst, src, sizeof src); // dst 是另一份內容
p[0] = 99;
// src[0]=99；dst[0] 仍是 10
```

陣列宣告後不能用 `dst=src` 整體賦值。含指標的 struct 即使用 `b=a` 複製，裡面的指標仍指向原 buffer，沒有深層複製。

## buffer 的生命週期與範圍

| 問題 | 為什麼會出錯 |
|---|---|
| 陣列 a[8] 存取 a[8] | 索引合法範圍是 0..7 |
| 回傳函式區域陣列的位址 | 函式返回後那個物件已失效 |
| 非同步運算尚未完成就重用 buffer | worker／DMA 還可能在讀寫它 |
| queue 只傳了指標就以為內容被複製 | buffer 可能被下一筆覆蓋 |
| 把 uint8_t buffer 直接轉 uint32_t* 讀 | 需檢查對齊、長度與 C 型別存取規則 |

接收封包時按 byte 明確組合，或 memcpy 到合法型別物件後依協定處理 endian。不能假設任意位址都能解參考。
