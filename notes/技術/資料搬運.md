# 資料搬運與校驗

[← 回考場筆記入口](../README.md) · [指標與 bytes](../底層架構與資料流.md#c值位址與長度)

## 第一性原理：資料要換位置，就必須有人真的讀出再寫入

指標只記錄「資料在哪裡」；把位址指定給另一個指標，不會在目的區域產生一份內容。真正的複製要從來源讀值、寫到目的，並依數量重複。**DMA 把這種規律的讀寫交給專用硬體，CPU 則提供完整的工作描述。**

描述至少包含來源、目的、筆數、每筆寬度、兩端位址是否遞增。這些欄位決定實際存取的區域；設定錯了，硬體也只會照描述執行。啟動後資料還在途中，所以完成通知／等待與 buffer 生命週期也是搬運正確性的一部分。

### 要解決什麼問題

減少 CPU 逐筆搬資料的工作，並在合適情況下與計算重疊。校驗則處理「這串資料是否改變」：CRC／checksum 將指定範圍的資料累積成校驗值；支援的 DMA sniffer 可隨搬運累積，省去另一趟 CPU 掃描。校驗值有碰撞可能，CRC 也不能當成密碼學身分驗證。硬體支援與設定查 [DMA／sniffer API](https://www.raspberrypi.com/documentation/pico-sdk/hardware.html#group_hardware_dma)。

### 上機考可能怎麼出現

- **演練已出現：**[搬運引擎練習](../../demo/section2-3/README.md) 用 CPU thread 模擬 configure → start → wait → 取結果，示範 count、寬度與遞增。它不是實際硬體 DMA。
- **可能任務（推測）：**修正搬運配置、複製／填值／周邊收送，或把搬運與運算重疊。若題目指定校驗，再核對算法與 sniffer 模式；CRC 任務屬延伸推測。
- **具體例子：**8 個 `uint32_t` 應設 count=8、每筆 4 bytes，總共 32 bytes；若把 count 填 32，實際就搬 128 bytes。填固定值則來源不遞增、目的遞增。
- **動手順序：**先算兩端容量與總 bytes → 配寬度／count／遞增／必要 pacing → 啟動 → 保持 buffer 有效 → 等完成 → 驗證內容或校驗結果。

---

**把搬運交給另一個執行者，就要把工作說清楚：從哪讀、往哪寫、幾筆、每筆多大、位址要不要前進。**

## 你問過：為什麼不直接 dst=src

| 寫法／方法 | 實際做什麼 |
|---|---|
| 指標 `dst = src` | 讓 dst 指向 src，沒有產生另一份內容 |
| 已宣告陣列 `dst = src` | C 陣列不能這樣整體賦值 |
| for 逐筆複製／memcpy | CPU 執行搬運；memcpy 的長度單位是 bytes |
| 演練的 engine.c | 另一條 CPU thread 執行搬運迴圈，模擬非同步引擎 |
| 硬體 DMA | 專用硬體操作匯流排，CPU 可以做其他工作 |

DMA 仍需設定、等待、記憶體頻寬；資料很少時，設定成本可能比直接複製高。演練 engine 不是免費的硬體加速。

## 本 repo 的工作單怎麼讀

| 欄位 | 意思 | 複製 8 個 uint32_t |
|---|---|---|
| src | 從哪個位址讀 | src 陣列起點 |
| dst | 往哪個位址寫 | dst 陣列起點 |
| count | 搬幾筆 | 8 |
| size | 每筆多大 | XFER_32，即 4 bytes |
| src_increment | 下一筆是否換下一格來源 | true |
| dst_increment | 下一筆是否換下一格目的 | true |

**總 bytes = count × 每筆 bytes。** 在此 8-bit byte 平台，uint32_t=32 bits=4 bytes，因此 8 筆是 32 bytes。

## 你問過的 make mistake

```c
job.count = N;                     // 正確：N 筆
wrong.count = N * sizeof(uint32_t); // 故意錯：把總 bytes 放進筆數
```

目前 N=8：錯誤 count=32，每筆仍 4 bytes，所以搬了 **128 bytes**，比預期多 4 倍。原範例預留較大的陣列以展示超出預定範圍；真正只配置 8 個元素會越界。

官方原值 N=4096：正確 4096 筆／16384 bytes；錯誤 16384 筆／65536 bytes。輸出的 spins 是等待期間主程式轉了幾圈，不是搬運筆數或吞吐量。

## 只改 increment，工作就不同

| 工作 | src_increment | dst_increment | 資料流 |
|---|---|---|---|
| 複製陣列 | true | true | src[0]→dst[0]，src[1]→dst[1]… |
| 固定值填滿 | false | true | 同一個 pattern→dst[0]、dst[1]… |
| 收周邊資料到陣列 | false | true | 固定周邊位址→連續記憶體 |
| 陣列送到周邊 | true | false | 連續記憶體→固定周邊位址 |

周邊傳輸還要查 DREQ／pacing、資料寬度與存取規則，不能只改布林值。

## start 與完成是兩回事

```text
claim → configure → start → CPU 可做其他事 → wait 完成 → 讀結果 → release
```

| 階段 | 需要注意 |
|---|---|
| claim | 通道數有限，要處理取得失敗 |
| configure | 位址、長度、對齊、範圍正確 |
| start 後、完成前 | src/dst 仍有效，不能提早釋放或拿去做衝突存取 |
| wait 後 | 才能依 API 保證使用結果 |
| release | 資源歸還，避免後續拿不到通道 |

複製工作單 struct 只是複製其中的位址，不會把 src/dst 的資料一起複製成新 buffer。

## Pico SDK 真 DMA 名稱對照

| 步驟 | 常見 API |
|---|---|
| 取得通道 | `dma_claim_unused_channel` |
| 設資料寬度 | `channel_config_set_transfer_data_size` |
| 設位址遞增 | `channel_config_set_read_increment`／`write_increment` |
| 配置工作 | `dma_channel_configure` |
| 等完成 | `dma_channel_wait_for_finish_blocking` |
| 歸還 | `dma_channel_unclaim` |

`dma_channel_configure` 的參數順序是 **寫入位址在前、讀取位址在後**。RP2350 的 transfer count 還有模式欄位；依現場 SDK 的宣告／helper 設定，別把模擬 struct 直接套上去。

## 校驗周邊：DMA sniffer

**sniffer 觀察指定 DMA 通道搬過的資料，累積 CRC／checksum。** 搬完才讀結果；它是共用資源，不能假設每個通道各有獨立校驗器。

官方演練 PDF 印刷頁8提到「搬運／校驗周邊」。若正式題目要求相符的校驗，可以查以下 API；不是看到 DMA 就一定需要啟用。

| 查什麼 | API／規格 |
|---|---|
| 啟用通道與模式 | `dma_sniffer_enable(channel, mode, force_channel_enable)` |
| 設定初值／讀結果 | `dma_sniffer_set_data_accumulator`／`dma_sniffer_get_data_accumulator` |
| byte 順序／輸出反轉／反相 | `dma_sniffer_set_byte_swap_enabled`、`dma_sniffer_set_output_reverse_enabled`、`dma_sniffer_set_output_invert_enabled` |
| 結束使用 | `dma_sniffer_disable` |

SDK 模式含 CRC-32、CRC-16-CCITT、反轉輸入 bits 的 CRC 模式、XOR 與32-bit加總。**同名 CRC32 不保證同一版本**，先對照 polynomial、初值、反射、最後 XOR 與處理範圍。

bit reversal 是反轉位元順序，byte swap 是交換 byte 順序，不是同一件事。每筆獨立校驗要依規格重設累積值；不能把各分段 CRC 直接相加／XOR 當成整段 CRC。

## 找原始碼與錯誤

[main.c](../../demo/section2-3/transfer-engine/main.c) 決定工作；[engine.h](../../demo/section2-3/transfer-engine/engine.h) 定義型別／函式介面；[engine.c](../../demo/section2-3/transfer-engine/engine.c) 執行搬運。[Makefile](../../demo/section2-3/Makefile) 編譯連結兩份 .c。

| 症狀 | 先查 |
|---|---|
| 多寫／少寫 | count 的單位、size、目的容量 |
| 全部一樣 | src_increment 是否關閉 |
| 只有一格變 | dst_increment 是否關閉 |
| 偶爾舊資料／損壞 | 沒等完成、buffer 被重用、同步或對齊錯誤 |

原模擬引擎用 volatile busy，缺少完整跨 thread 同步，連 wait 內部也受影響；用來讀工作配置概念，不當成正式同步範本。
