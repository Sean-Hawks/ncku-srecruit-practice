# 底層架構：先分清誰執行、資料放哪

[← 回考場筆記入口](README.md)

**程式要做事，必須有執行者、放資料的空間，以及交換資料的方法。** 下面幾種技術分別處理這三件事。

## 一張表分清角色

| 名稱 | 是什麼 | 在做什麼 |
|---|---|---|
| CPU 核心 | 執行指令的硬體 | 讀數值、計算、寫結果 |
| 暫存器 | 執行者旁的小型儲存位置 | 暫放位址、數值與運算結果 |
| RAM／記憶體 | 儲存程式資料的空間 | 放陣列、封包、模型、共享變數 |
| ISA | CPU 能讀懂的指令規格 | 規定機器碼如何解讀、執行 |
| PIO | 能執行自己短指令的周邊 | 管接腳時序、移位與資料流 |
| FIFO | 有限容量、先進先出的儲存佇列 | 在兩個速度不同的執行者間暫存資料 |
| DMA | 搬資料的硬體引擎 | 按設定在記憶體／周邊之間搬運 |
| ROS 2 | 程式之間通訊的軟體框架 | 用具名稱、型別的 topic 交換訊息 |
| Docker | 隔離程式環境的工具 | 提供指定套件、路徑與程序環境 |

## CPU 算一個答案時

```text
RAM 裡的輸入 → CPU 讀到暫存器 → 執行加法等指令 → 結果寫回
```

C 的 `out = in * 2` 經編譯後成為 CPU 指令。CPU 執行的是機器碼；`ISA` 是解讀這些碼的規則。`x` 是數值，`&x` 是它的位址，`*p` 是去 p 指向的位置讀寫內容。

例如位址 `0x1008` 裡存 `42`：**位址回答「在哪」，42 回答「裡面是什麼」。** `lw` 會取內容；單純把位址加 8 不會自動讀內容。詳見 [ISA](技術/ISA與指令編碼.md)、[C 指標](技術/C記憶體與指標.md)。

## ROS 2 的資料流

```text
publisher 程式 → /number → processor callback → /double → echo
```

topic 是通道；callback 是收到訊息才執行的函式；echo 是另一個接收者。`/double` 只是通道名，真正乘幾倍要看 callback 的計算式。processor 沒輸入時等待，通常不會自己印東西。詳見 [ROS 2](技術/ROS2.md)。

## PIO 的資料流

原演練 echo 範例假設 autopull 已設定：

```text
CPU → TX FIFO → OSR → X → ISR → RX FIFO → CPU
         自動補入    out   in    push      讀取
```

每個箭頭是一次資料移動。FIFO 不是計算函式；`push` 是把資料放進 RX FIFO 的指令。CPU 還要讀取，才真正拿到結果。PIO 是另一個執行者，有自己的 ISA，不能直接塞一般 C 演算法進去。詳見 [PIO](技術/PIO.md)。

## thread、DMA、多板各自在分什麼工

| 方式 | 誰幫忙 | 資料怎麼交接 |
|---|---|---|
| thread／多核心 | 其他 CPU 執行路徑／核心 | 同一程序可共享記憶體，需要同步 |
| DMA | 專用搬運硬體 | 填來源、目的、筆數、寬度，啟動後等完成 |
| 多板 | 另一塊板子的 CPU | 各有記憶體，必須透過通訊送資料與結果 |

原演練 engine.c 用 thread 模擬搬運，因此仍消耗 CPU。真 DMA 才是硬體幫忙搬。**start 表示開始，完成後才能把輸出當成有效答案。**

詳見 [平行運算](技術/平行運算.md)、[資料搬運](技術/資料搬運.md)。

## 讀陌生程式只追這條線

```text
從哪收到 → 放進哪個 buffer → 誰處理 → 何時完成 → 往哪交答案
```

每一段查「型別、長度、單位、誰能讀寫」。卡住就找上一段是否真的有交出資料；偶爾錯就查越界、未等完成、共享資料與 buffer 被提早重用。
