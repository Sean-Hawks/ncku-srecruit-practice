## 1 ISA：把機器碼解成動作

**可能題目：**給十六進位指令、暫存器／記憶體初值，要補解碼器或小型執行器。也可能只要求辨識指令、計算存取位址。

**看到什麼算同類題：**opcode、decode、register、rd／rs1、immediate、PC、instruction memory。

### 已解讀例子

題目若指定 RV32I，x6=0x1000、位址 0x1008 的 32-bit 內容為 42：

| 指令數值 | 解碼 | 執行結果 |
|---|---|---|
| 0x00830293 | addi x5,x6,8 | x5=0x1008，只做加法 |
| 0x00832283 | lw x5,8(x6) | 先算 0x1008，再讀內容，x5=42 |
| 0xFFC30293 | addi x5,x6,-4 | x5=0x0FFC；0xFFC 是有號 12-bit 的 -4 |

### 解題順序

1. 找題目要求的 ISA 與指令範圍，先拿到每種格式的欄位圖。
2. 依 opcode、funct3／funct7 辨識指令，用移位＋mask 取欄位。
3. 拼回立即數，依位寬處理正負，再讀來源暫存器。
4. 區分「只算值」與「算位址後讀寫記憶體」。若有執行器，更新目的暫存器與 PC。
5. RV32I 的 x0 寫入無效；branch 目標通常是目前 PC 加 byte 偏移，不能沿用一般 PC+4。

**先完成正確版本，再考慮優化：**減少重複解碼；只有規格允許且指令內容不會改變時，才考慮快取解碼結果。

**最易錯：**負立即數當正數、把位址當內容、所有指令都用同一格式、漏掉 x0／PC 規則。

[查欄位／編碼／定址表](技術/ISA與指令編碼.md)

## 2 PIO：接收一筆資料，處理後交回

**可能題目：**給 .pio 與 CPU 啟動程式，要求補資料搬移、位元流或接腳操作；也可能要找出不回傳、位元順序錯誤的原因。

**看到什麼算同類題：**TX／RX FIFO、OSR／ISR、out／in／push、shift、threshold、autopull。

### 已解讀例子

假設完整 32-bit 傳輸與 autopull 已設定，CPU 送入 21：

```text
TX FIFO → OSR → out x,32 → X=21 → in x,32 → ISR=21 → push → RX FIFO
```

| 變化 | 結果 |
|---|---|
| out、in 都用 X | 回 21 |
| out 改 Y、in 仍讀 X | 回 X 的舊值，不是剛收到的 21 |
| out 後加 set x,7，再 in X／push | 回 7 |
| CPU 只送不讀，RX 塞滿 | 阻塞式 push 會等，整條路可能停住 |

### 解題順序

1. 找主機送出的格式與期望回傳格式，數清每筆幾 bits／幾個 FIFO 項目。
2. 對每條指令標「來源 → 目的」，先確保一筆輸入對上一筆輸出。
3. 若要取 8 bits，連同 shift 方向、其餘 24 bits 如何消耗、ISR 如何排列一起處理；只改 32→8 不夠。
4. CPU 端確認載入、初始化、啟用、送／收都有接上；再看腳位、時鐘與 wait 條件。
5. 批次資料才考慮 DMA 餵／收 FIFO，避免 CPU 一直只寫不讀。

**最易錯：**把 push 當 CPU 已收到、手動 push 與 autopush 重複、FIFO 互等、拿 CPU ISA 解 PIO。

[查資料路徑／指令／CPU API](技術/PIO.md)

## 3 ROS 2：收到資料，算完再回傳

**可能題目：**訂閱指定 topic，解析資料，呼叫提供的演算法／板子處理，再發布指定結果。ROS 可能負責資料入口與結果交付，計算本體另有規格。

**看到什麼算同類題：**create_subscription、callback、message type、publish、topic 名稱。

### 已解讀例子

假設題目定義：輸入整數的 bits15..8 是 A、bits7..0 是 B，輸出 A+B。

```text
輸入 773 = 0x0305
A = (773 >> 8) & 0xFF = 3
B = 773 & 0xFF = 5
輸出 8
```

### 解題順序

1. 從 PDF／訊息宣告查實際 topic、型別、欄位、長度、結果順序。
2. 找 callback 的計算／呼叫處，保留題目已建好的通訊骨架。
3. 收到資料 → 轉成算法要的格式 → 算 → 建輸出訊息 → publish。
4. 沒輸出時，沿 node → 接線 → 輸入 echo → callback → 輸出 echo 找斷點。
5. 若單次計算很久而影響收訊，再用 queue 分開收送與運算；結果仍帶原工作編號。

**最易錯：**topic 名稱差一字、型別錯、把 echo 當運算程式、耗時 callback 阻塞其他工作、結果格式不符。

[查 ROS 與診斷命令](技術/ROS2.md)

## 4 平行運算：把正確程式變快

**可能題目：**一批資料分給兩核心／多個 worker，或縮短鎖持有時間；如果有多板，主機再負責傳送與收齊。

**看到什麼算同類題：**thread、worker、core、mutex／spinlock、shared buffer、queue、join。

### 已解讀例子

100 筆互相獨立的工作：A 處理 0..49，B 處理 50..99。每筆結果寫自己的位置，兩邊完成後才交答案。B 先回傳並不代表它的答案應排前面。

若要求總和：A 算局部和、B 算局部和，最後相加。若要求每筆分類：按 ID 還原 100 筆分類，**不能把類別編號相加**。

### 解題順序

1. 查每筆是否獨立、演算法是否有共享可變暫存區；可共享唯讀模型不代表所有狀態都安全。
2. 先切不重疊的工作範圍，給各 worker 獨立輸出／暫存區。
3. 使用 SDK 的 thread／核心／task API 啟動，等待所有必要工作完成再合併。
4. 必須共享的更新才同步；獨立耗時運算留在鎖外。
5. 比較整批完成時間。資料大小相近先固定切塊；快慢差大再考慮空閒 worker 領下一筆。

**最易錯：**counter++ 沒保護完整讀改寫、queue 只傳指標卻重用 buffer、模型暫存區互踩、還沒完成就回傳。

[查鎖／分工／封包與多板](技術/平行運算.md)

## 5 DMA：描述搬運，取代 CPU 逐筆搬

**可能題目：**把複製、填值、周邊收送改用搬運引擎，或找出 count／遞增設定錯誤。

**看到什麼算同類題：**DMA、channel、src／dst、transfer size、count、increment、busy／wait、DREQ。

### 已解讀例子

| 要求 | 正確工作描述 |
|---|---|
| 複製 64 個 uint16_t | count=64，每筆2 bytes，總128 bytes，來源／目的都遞增 |
| 用 0x1234 填滿同一個目的陣列 | count=64，每筆2 bytes，來源固定指向 pattern，目的遞增 |
| 錯把 count 填128 | 會傳128筆，即256 bytes，可能越界 |

### 解題順序

1. 算清楚元素數、每筆 bytes、兩端容量與對齊。
2. 取得通道，設定來源、目的、寬度與遞增；周邊路徑另查 DREQ 節奏控制。
3. 啟動後，buffer 保持有效；等完成後才讀結果、重用或釋放。
4. 沒通道時依框架排隊／等待或回報，不能假設永遠拿得到。
5. 有獨立工作才讓 CPU 與 DMA 重疊；只有立刻 start→wait，未必比 memcpy 快。

**最易錯：**把 bytes 當 count、讀寫位址順序放反、忘了等完成、buffer 太早失效、忘記歸還通道。

[查搬運設定與真 SDK 對照](技術/資料搬運.md)

## 6 校驗：利用周邊算 CRC 或 checksum

**可能題目：**給一段資料與指定校驗演算法，要正確計算並加速。PDF 印刷頁8提到「搬運／校驗周邊」；Pico SDK 的 DMA sniffer 確實支援 CRC 等模式，這是值得保留的推測方向。

**簡介：**checksum／CRC 把一串資料算成校驗值，用來偵測資料是否有變。DMA sniffer 可以在觀察搬運資料時累積指定校驗。

### 解題順序

1. 讀清楚算法版本、資料範圍；CRC 還要查 polynomial、初值、輸入／輸出反射與最後 XOR。
2. 用題目參考函式或標準測資當正確答案，再對照硬體模式與每個設定。
3. 將待校驗的相同 bytes 交給 DMA，設定 sniffer／初值，啟動後等完成，才讀累積結果。
4. 每筆新工作依規格重新設初值；多路工作要協調 sniffer 這個共用資源。
5. 小資料可能 CPU 比較快；比較整批耗時，不能只量啟動呼叫。

**已解讀例子：**8 個 uint32_t 是32 bytes。若題目校驗的是 payload，就處理這32 bytes；別把「筆數8」誤認成「長度8 bytes」，也別把封包 header 或未初始化的 padding 算進去。

**最易錯：**看到 CRC32 就假設版本相同、byte／bit 反轉混淆、忘記最後 XOR、把多段 CRC 直接相加或 XOR 當成整段 CRC。

[查 DMA sniffer API 與參數](技術/資料搬運.md#校驗周邊dma-sniffer)

## 如果題目把幾項放在一起

可能的整合形狀是：**ROS 收資料 → 解析工作 → 交 CPU／PIO／DMA 的適合路徑 → 等完成 → 回結果**。各項也可能分開出題，不必為了使用所有技術而重寫整個系統。

解題共通順序：**看輸入輸出與評分指標 → 找骨架的接收／處理／回傳位置 → 完成正確基準 → 量最慢一段 → 只改那一段。**

ESP32、eBNN、排序、SHA 的線索只來自歷屆心得，集中在 [一頁備查](技術/歷屆延伸.md)。不把特定模型或 SHA 版本當今年答案。
