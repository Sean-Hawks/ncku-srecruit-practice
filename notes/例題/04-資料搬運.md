# 04 4096 改成 8，搬運量怎麼變

打開 [transfer-engine/main.c](../../demo/section2-3/transfer-engine/main.c)。

## 原版：4096 筆，每筆 4 bytes

先找三個地方：

```c
#define N 4096
```

```c
.count = N,
.size = XFER_32,
```

`N` 是要搬幾筆；`XFER_32` 表示每筆 32 bits，也就是 4 bytes。

所以實際搬運量是 **4096 × 4 = 16384 bytes**。

## 改一次：只搬 8 筆

只改：

```c
#define N 8
```

在 container 的 `/demo/section2-3` 重新編譯執行：

```bash
make run-transfer-engine
```

主要輸出變成：

```text
1. copy 8 words          dst matches src
2. fill 8 words          every word is 0xA5A5A5A5
```

現在每項工作只搬 **8 × 4 = 32 bytes**。主程式「跑幾圈」會變動，先不用比較它。

## 原本就有的第二種設定：複製變填值

對照原碼的 copy 與 fill：

```text
copy：讀 src[0] → src[1] → src[2] → …
fill：讀 pattern → pattern → pattern → …
```

copy 的來源是陣列，而且 `src_increment=true`。fill 的來源指向單一 pattern，而且 `src_increment=false`。目的端都逐格前進。

所以 fill 不是生成新數字，只是不斷讀取同一格，再寫入下一個目的位置。

## 再跑一次：把 bytes 誤當成筆數

保持 N=8，執行：

```bash
make mistake
```

原碼故意寫：

```c
wrong.count = N * sizeof(uint32_t);
```

它算出 32，卻把 32 填進「筆數」欄位。結果變成：

```text
count given as 32 (the byte count) instead of 8
the engine moved 32 words and wrote 24 past the 8 you meant
```

程式原本多留了四倍 buffer，才適合演示這個錯誤；不要另用只有 8 筆的 buffer 照做。

## 換你試

將 N 改成 16：

1. 正常複製幾 bytes？
2. mistake 會搬幾筆？
3. 超過原本想搬的幾筆？

<details>
<summary>看答案</summary>

正常 16 × 4＝64 bytes。mistake 搬 64 筆，比原本想搬的 16 筆多 48 筆。

</details>
