# 05 追一筆 PIO 資料，X 改 Y 會怎樣

打開 [demo_pio.pio](../../demo/section2-2/demo_pio.pio)。這題依原材料閱讀與手算，沒有完整的硬體啟動程式，不需要執行或燒錄。

## 先把名字當成幾個盒子

- TX FIFO：CPU 送出的資料先排在這裡。
- OSR：準備被 out 取走的資料。
- X、Y：程式可以使用的兩個暫存器。
- ISR：in 收進來、準備 push 的資料。
- RX FIFO：送回 CPU 的資料排在這裡。

範例假設 autopull 等設定已完成，會從 TX FIFO 補資料到 OSR。

## 原版：送入什麼，送回什麼

假設 CPU 送入 `0x12345678`：

```pio
out x, 32
in  x, 32
push
```

| 執行後 | 值在哪裡 |
|---|---|
| 資料由 FIFO 補進 OSR | OSR 有 0x12345678 |
| out x, 32 | X 得到 0x12345678 |
| in x, 32 | ISR 得到 0x12345678 |
| push | RX FIFO 收到 0x12345678，CPU 可讀回 |

32 bits 是完整的一筆，所以這段是在原樣送回資料。

## 改一次：兩個 x 都改成 y

```pio
out y, 32
in  y, 32
push
```

仍然送回 `0x12345678`。你只是把中途暫放的盒子從 X 換成 Y，資料沒有被計算或修改。

這也說明：`out` 看的是「從 OSR 送到哪裡」，`in` 看的是「從哪裡收到 ISR」。

## 換你試

只改第一個 x，第二個不改：

```pio
out y, 32
in  x, 32
push
```

如果執行前 X=7，CPU 送來 99，最後會送回哪個值？

<details>
<summary>看答案</summary>

**7**。99 被放到 Y，但下一行讀的是 X。若不知道 X 原本的值，就無法只憑送入的 99 判斷回傳值。

</details>

**過關：**能逐行指著來源與目的，不把 out、in 直接理解為 CPU 的送出與收到。
